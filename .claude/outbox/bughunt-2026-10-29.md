# Bug hunt — waterplane-plugin-copilot, 2026-10-29

Scope: the whole plugin at 5aed37e (≈2.9k source lines; `fake/` and `scripts/` are test tooling and were left out). The contract is `~/dev/usmc/packages/shared/src` and `docs/plugins-api.md`. Six hunters searched the code, one area each: ledger+caps, session-log+slots, transcript+conversations, dialogs, hooks+channel+delivery, host+launch+setup. A fresh verifier was then given only each finding's code location and asked to refute it. Nothing was fixed or committed.

Full hunter write-ups: `.claude/outbox/bughunt-2026-10-29/{ledger,sessionlog,transcript,dialogs,hooks,host}.md`. Verifier verdicts: `.claude/outbox/bughunt-2026-10-29/verdicts.md`. Throwaway proof scripts are in the session scratchpad (`verify-*/`).

**Totals:** 35 findings. 25 CONFIRMED and 7 PLAUSIBLE are kept; 3 were refuted. Two are high severity.

## High

### 1. S1: asking for Default from Plan leaves Copilot in Autopilot (no approvals). CONFIRMED.
- **Location:** `sessionlog.mjs:194-198` (`mode.set`), `sessionlog.mjs:~40` (`modeOf`).
- **Scenario:** the session is in plan and the phone asks for "default". Copilot's Shift+Tab cycle is interactive → plan → autopilot → interactive (`session.mode_changed` in `test/fixtures/copilot-1.0.98/probe-main-1098.jsonl`). `mode.set` always sends one `\x1b[Z`, so one press from plan lands in **autopilot**.
- **What the host then does:** `modeOf("autopilot")` is null. The host's ladder (usmc `livemode.ts:205-245`) stops with "mode stopped being readable", and a retry is refused at `:235`.
- **Result:** a request for a *safer* mode leaves the session running tools without approval.
- **Evidence:** the verifier's script gives `{keys:'\x1B[Z'}` from plan→default. The cycle order comes from the fixture.
- **Fix:** count the presses from the measured cycle (plan→interactive = 2 presses; the host allows up to 8 keys). Also make `modeOf` read autopilot, so the ladder can see and correct it instead of stopping blind.

### 2. L1: a `/fork` counts the parent's AI credits twice. CONFIRMED.
- **Location:** `ledger.mjs:107-121`.
- **Scenario:** the fork's `events.jsonl` repeats the parent's `session.usage_checkpoint` records (same ids, same running totals), then continues the parent's running total. The parent and the fork both count as launched, and each is folded from `prev = 0`.
- **Evidence:** the two 1.0.98 probe fixtures give `perDay {"2026-10-23": 1.650112}` with `sessions = 2`. The real spend is 1.04066 credits. The inflation reaches the hourly rows and the beside-figure.
- **Fix:** key checkpoints by event id across sessions, or start a fork's fold at its first checkpoint not copied from the parent (`forkedFrom` is known), so each credit is counted once.

## Medium-high

### 3. S5: reading a released session recreates its slot and steals the live session's id. CONFIRMED.
- **Location:** `host.mjs:204,273` (`idOf` → `router.slotFor`), `slots.mjs:64-75`, `channel.mjs:75-79`.
- **Scenario:** after `close()` releases a slot, any source read for that session (transcript, delivery, context, mode, tokens) builds a fresh slot. That slot has:
  - lost `forkedFrom`, so it reads the parent's log;
  - called `byId.set(id)`, taking the id from a live host session that resumed it, so hooks now go to the dead session;
  - never been released.
  
  An unbound recreated slot also rejoins `unbound`.
- **Evidence:** script output "B before release, A after" and "hook routes to old".
- **Fix:** read paths use `router.peek` (never create a slot) and answer "unknown" for a released session; only launch/attach creates slots.

### 4. H1: the hook runner trusts whatever answers on the sink port. CONFIRMED (mechanism); security.
- **Location:** `hook/post.mjs:31-43`, `hooks.mjs:50-60`.
- **Scenario:** while the daemon is down (restart or update) and Copilot keeps running in tmux, any local process, even another OS user's, can listen on the port. It then gets every prompt and tool input, and can answer `{"behavior":"allow"}` to every permission request. The runner prints that to Copilot.
- **Evidence:** the verifier's squatter on an ephemeral port answered `{"behavior":"allow"}`, and the runner printed it.
- **Contract:** the core's `hookSink()` is unauthenticated loopback by contract (`pluginapi.ts:547`).
- **Fix:** put a per-launch nonce in the generated hook command and have the handler echo or sign it. The runner prints only answers that carry the nonce, and only the expected shapes per hook. This can be done in the plugin; a core-side sink token would be the lasting fix.

## Medium

### 5. L2: a resumed plain-terminal session brings its whole terminal history into the ledger. CONFIRMED.
- **Location:** `ledger.mjs:97-98, 107-109`.
- **Scenario:** "launched" is decided per session, not per launch.
- **Evidence:** 5 credits at a terminal 10 days ago, then 1 credit via the plugin, gives `{"10-19": 5, "10-29": 1}`. This breaks the header (`:20-22`) and README (~152-155) "one population" promise.
- **Fix:** count only checkpoints after the first plugin launch of that id (the earliest OTel span or launch file time for the session).

### 6. L5: premium-request-only sessions vanish once any session reports `totalNanoAiu`. CONFIRMED.
- **Location:** `ledger.mjs:106, 112-113`.
- **Evidence:** A has 2e9 nano and B has 7 premium requests. The result is `unit {"AI credits": 2}`, while `sessions = 2`. The 7 requests are dropped without a word.
- **Fix:** keep both units in the document (each session in its own unit), or state the dropped sessions in a sentence, and stop counting them in `sessions`.

### 7. L6: the first scan of a >64 MiB events file gives a false "no usage" and a fresh-stamped undercount. CONFIRMED.
- **Location:** `jsonl.mjs:17, 33-38`; `ledger.mjs:83, 163-168, 196-202`.
- **Evidence:** a 70 MiB file first answers "Copilot has recorded no usage yet…". The second call gives 4 credits. `scannedAt` is now, so the span cut trusts the result.
- **Also:** `build()` is synchronous; it blocked the event loop for 93 ms.
- **Fix:** while a tail still has a backlog, leave out or back-date `scannedAt` (or answer `available: false` with "still reading"), and yield between windows.

### 8. T1: subagent prompts become top-level turns. CONFIRMED.
- **Location:** `transcript.mjs:100-115`.
- **Evidence:** `probe-fork-fleet-1098.jsonl` folds into 5 turns instead of 3. Turns 4 and 5 are "Return exactly … b/a". They carry a top-level `agentId`, and the newer one becomes `last`, so later `turn_end` and tool events land on it.
- **Delivery:** not affected (host `sourceMatch` matches the whole text).
- **Fix:** after updating `lastSeen`, skip or route events whose `ev.agentId` is set; add a turn-count assertion to the wp4c test.

### 9. T2: `agentsRunning` stays stuck after a killed CLI, for any client polling with `since`. CONFIRMED.
- **Location:** `transcript.mjs:174-180` vs `:245-249`; host `record.ts:313-314`.
- **Scenario:** the 10-minute "a killed CLI writes no ending" rule runs only inside `doc()`. The file's mtime freezes, so the host answers "unchanged" and never calls it.
- **Fix:** make `updatedAt` max(mtime, the time the quiet-rule fires) so the stamp moves when the rule changes the answer.

### 10. T3: a turn's `files` misses apply_patch and large edits, and holds absolute paths. CONFIRMED.
- **Location:** `transcript.mjs:186-193` with the 2000-char `pretty` cut at `:57-62`.
- **Evidence:**
  - apply_patch takes string arguments, so it never contributes a path.
  - Inputs over 2000 chars fail `JSON.parse`, so their paths are dropped.
  - The paths are absolute; the wire contract (`transcript.ts:114`) says repo-relative.
  
  In the fixture, a turn that wrote `plan.md` shows `files = []`.
- **Fix:** collect paths from the raw arguments before they are cut, parse apply_patch's `*** Update/Add File:` headers, and make paths relative to the session cwd.

### 11. S2: the wrong host session adopts a fork when two share one Copilot id. CONFIRMED.
- **Location:** `slots.mjs:64-71, 130-147`.
- **Scenario:** `followFork` walks `byHost` in insertion order, so the older host session takes the fork id, whichever one typed `/fork`.
- **Fix:** only the slot that `byId` maps the parent id to may follow the fork.

### 12. S3: a stale "Forked this session into" line rebinds a slot. CONFIRMED.
- **Location:** `sessionlog.mjs:56-62`, `slots.mjs:130-147`.
- **Scenario:** `forkTo` is never cleared. A resumed parent X immediately reads `forkTo = B`. When B is then launched with `--continue`, its first hook re-points X's slot to B, and the `--continue` slot never binds.
- **Fix:** let `followFork` act only on fork lines written after the slot bound (compare timestamp or offset), and clear `forkTo` once it is adopted.

### 13. D3: a re-fired hook makes a second phone box. CONFIRMED.
- **Location:** `dialogs.mjs:500-505, 573-590`.
- **Scenario:** `s.open.has(tcid)` checks box ids, but a box published under a synthesized id has since learned its real `toolCallId`.
- **Evidence:** script gives `asked [copilot-perm-1000-1, C9]`, and the old hook stays pending. Tapping the stale box reports "answered" while Copilot keeps waiting.
- **Fix:** match re-fires on `x.toolCallId` (or re-key the box when it learns the id).

### 14. D1: a non-shell hook can get a parallel call's id and block the phone for the rest of the session. PLAUSIBLE.
- **Location:** `dialogs.mjs:552-560, 463-468`.
- **Scenario:** when only a parallel `view`'s start is on disk as an `edit` hook fires, the box gets view's id. The real `permission.requested` then makes a second box. The stale box blocks every later terminal dialog ("another Copilot dialog is in front") until the session restarts.
- **Why plausible:** the measured fixture order (both starts land 2 ms apart) avoids it. It fails closed.
- **Fix:** take an id only when the hook's own tool name or arguments match the candidate; otherwise synthesize. Let a box whose tool call completed be dropped even in hook phase.

### 15. D5: an answer can drive the wrong ask_user form when two have the same choices. PLAUSIBLE.
- **Location:** `dialogs.mjs:141-158, 436-441`.
- **Scenario:** `askCursor` ignores the question text. In the script, answering "Add a README?" with Yes accepts "Delete the DB?".
- **Why plausible:** concurrent ask_user calls are not observed.
- **Fix:** also require the question's message (its first row) on screen.

### 16. S4: mode, a pending plan approval and running subagents carry across process runs. PLAUSIBLE.
- **Location:** `sessionlog.mjs:51-128`.
- **Scenario:** `session.start`, `session.resume` and `session.shutdown` are ignored. After a resume, a pending `exit_plan_mode` is still offered, and approving it types "2" into a fresh prompt.
- **Why plausible:** Copilot's own mode on resume is unmeasured.
- **Fix:** on `shutdown`/`resume`, close plan approvals and running agents and mark the mode unknown until the next `mode_changed`.

## Refuted (dropped)
- P5 no `deactivate`: the host registry cleans up itself (`pluginregistry.ts:311-357`), and deactivate is optional.
- H2 `--continue` `createsRecord = true`: a deliberate, documented deviation (`slots.mjs:10-14`). The residual risk is covered in S3 and S5.
- H5 hook payload >1 MB: the core turns it into `{}`, and Copilot falls back to its own dialog, which `dialogs.mjs` still publishes.

Out of this hunt's reach: `launch.mjs:154` reuses `<id>.jsonl` for every resume; if Copilot's exporter truncates that file on open, earlier token spans are lost. This needs the real binary to check.

## Fix status (same day, uncommitted working tree)

- **Fixed, each with a regression test:** every kept finding except the ones named below. Test files are `test/*-fixes.test.mjs`. A fresh review then found 5 regressions in the fixes (`.claude/outbox/bughunt-2026-10-29/review.md`); all are fixed.
- **Suite:** `node --test` gives 206/206.
- **Diff:** 24 files changed plus 9 new test files. Nothing is committed.

**Partly fixed or decided differently:**
- **S1:** plan → default now sends 2 presses and lands in interactive. Autopilot still reads `null`, because no contract mode fits it faithfully, so the phone cannot bring a session out of autopilot. Reading it as `bypassPermissions` would be a one-line change in `modeOf`, but that is the owner's call.
- **S4 / R3:** the mode is unknown after a process start or resume until a Shift+Tab, a plan-mode prompt or a permission prompt. That is no worse than HEAD. An absent `agentMode` could mean interactive, but this can't be proven until one autopilot prompt is captured.
- **P2:** COPILOT_HOME is now read once for everything, so a change made from the phone applies on restart. Making it live would need getters in the ledger and transcript modules.
- **P6:** old OTel files are not deleted, because they are the record of which sessions were launched. They are skipped after being read once, and spans older than 50 days are evicted.
- **R5:** a Copilot session launched before this update (old hook command line) still gets unsigned answers, which is the pre-update behaviour. Every new launch is signed.
- **D5 / R4:** ask_user picks need the whole question plus its field rows on screen. Forms with no title or description are not captured yet and may be refused, which fails safe.

**Not changed:** P1 (apiVersion "2.2" while using 2.3 fields) is the owner's decision.
